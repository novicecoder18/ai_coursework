Multi-Resource Workload Allocation — Coursework (v1 draft)¶

Select a subset of candidate AI models for an edge platform so that total utility is maximised without exceeding any of the $m$ hardware capacities (0-1 multi-dimensional knapsack):

$$\max f(\mathbf{x})=\sum_{j=1}^{n}p_jx_j \quad\text{s.t.}\quad \sum_{j=1}^{n}r_{i,j}x_j\le b_i\;\;\forall i=1..m,\qquad x_j\in\{0,1\}$$

Part Instance Content
1 n=28, m=2 Hill-climber baseline, 30 independent runs
2 n=90, m=5 Population-based metaheuristic (genetic algorithm with greedy repair)
3 n=90, m=5 Controlled study: repair vs penalty constraint handling, 30 paired runs, Wilcoxon test

All search code is written from scratch with NumPy (no metaheuristic frameworks). Every run uses a fixed seed (seed = 0..29).

0. Shared building blocks¶

  • Solution = binary vector x. Neighbour = flip one bit (add or remove one model).
  • Feasible = every resource usage d @ x is within its capacity.
  • Constraint handling – greedy repair. An infeasible vector is repaired by removing the selected model with the lowest efficiency until feasible. Efficiency $e_j=p_j/\sum_i (r_{i,j}/b_i)$ is utility per unit of capacity-normalised resource cost; normalising by $b_i$ makes resources with different units comparable. Optionally, a fill step then adds unselected models (best efficiency first) while they still fit, so repaired solutions are not wastefully sparse.
  • Budget. Cost is counted in fitness evaluations (one utility/feasibility evaluation of one candidate), identical for every algorithm so comparisons are fair.

def utility(x, u):
    return float(u @ x)

def is_feasible(x, d, b):
    return bool(np.all(d @ x <= b))

def violation(x, d, b):
    # total capacity-normalised excess over all resources (0 when feasible)
    return float((np.maximum(d @ x - b, 0.0) / b).sum())

def efficiency(u, d, b):
    # utility per unit of capacity-normalised resource cost
    return u / np.maximum((d / b[:, None]).sum(axis=0), 1e-12)

def repair(x, u, d, b, eff, fill=True):
    # drop worst-efficiency models until feasible; optionally greedily add best-efficiency models that still fit
    x = x.copy()
    use = d @ x
    if np.any(use > b):
        sel = np.where(x == 1)[0]
        for j in sel[np.argsort(eff[sel])]:          # worst first
            if np.all(use <= b):
                break
            x[j] = 0
            use -= d[:, j]
    if fill:
        free = np.where(x == 0)[0]
        for j in free[np.argsort(-eff[free])]:       # best first
            if np.all(use + d[:, j] <= b):
                x[j] = 1
                use += d[:, j]
    return x

def curve(histories, length):
    # stack best-so-far histories (one entry per evaluation) onto a common length
    return np.array([np.pad(h[:length], (0, max(0, length - len(h))), mode="edge") for h in histories])

Part 1 — Baseline discrete local search (Instance 1, n=28, m=2)¶

Algorithm: steepest-ascent hill climbing with random restarts.

  1. Start from a random bit vector and repair it (drop-only repair).
  2. Evaluate all one-bit-flip neighbours (each repaired), visited in random order; move to the best one if it improves the current solution.
  3. At a local optimum (no improving neighbour) perform a random restart instead of stopping, so the budget is always used.
  4. Stop after 3000 fitness evaluations.

Design choices

Choice Decision Why
Operator single bit flip (add/remove one model) smallest move; neighbourhood size n=28 is cheap to scan fully
Constraint handling repair every start/neighbour (drop worst efficiency) search stays inside the feasible region, so every reported value is a valid deployment
Move rule steepest ascent on n=28 a full scan is cheap and gives deterministic progress per step
Local optimum random restart plain hill climbing stops at the first local optimum (lecture: exploration vs exploitation)
Fill step in repair off a flip that adds a model should not be silently undone by re-adding the dropped one; keeps neighbours distinct

Because m=2 and the capacities are integers, the exact optimum can be computed by dynamic programming. It is used only as a yardstick to judge the heuristic, never by the search itself.

def hill_climber(u, d, b, max_evals=3000, seed=0, restart=True):
    rng = np.random.default_rng(seed)
    n = len(u)
    eff = efficiency(u, d, b)
    new_start = lambda: repair(rng.integers(0, 2, n), u, d, b, eff, fill=False)

    cur = new_start(); cur_f = utility(cur, u); evals = 1
    best, best_f = cur.copy(), cur_f
    hist = [best_f]                                   # hist[k] = best-so-far after k+1 evaluations
    while evals < max_evals:
        move, move_f = None, cur_f
        for i in rng.permutation(n):                  # scan the whole neighbourhood
            if evals >= max_evals:
                break
            nb = cur.copy(); nb[i] ^= 1
            nb = repair(nb, u, d, b, eff, fill=False)
            f = utility(nb, u); evals += 1
            if f > move_f:
                move, move_f = nb, f
            if f > best_f:
                best, best_f = nb.copy(), f
            hist.append(best_f)
        if move is not None:
            cur, cur_f = move, move_f                 # climb
        elif restart and evals < max_evals:           # local optimum -> random restart
            cur = new_start(); cur_f = utility(cur, u); evals += 1
            if cur_f > best_f:
                best, best_f = cur.copy(), cur_f
            hist.append(best_f)
        else:
            break
    return best, best_f, hist, evals


def exact_optimum_2d(u, d, b):
    # DP over (capacity1, capacity2); valid because m=2 and demands/capacities are integers
    c1, c2 = int(b[0]), int(b[1])
    dp = np.zeros((c1 + 1, c2 + 1))
    for j in range(len(u)):
        r1, r2 = int(d[0, j]), int(d[1, j])
        cand = np.full_like(dp, -np.inf)
        cand[r1:, r2:] = dp[:c1 + 1 - r1, :c2 + 1 - r2] + u[j]
        dp = np.maximum(dp, cand)
    return float(dp.max())

Part 2 — Population-based metaheuristic (Instance 2, n=90, m=5)¶

Algorithm: genetic algorithm (GA) with greedy repair and elitism (lecture 4 cycle: initialise → evaluate → select → crossover → mutate → repair → replace).

Component Choice Technical rationale
Representation binary chromosome, gene j = deploy model j direct, no decoding needed
Initialisation random bits, then repaired diverse and feasible from generation 0
Selection tournament, k=3 scale-free (no fitness scaling needed), tunable pressure; k=3 is moderate so diversity is not lost too early
Crossover uniform, p=0.9 model indices carry no positional meaning, so there is no useful "building block" order that one-point crossover would preserve
Mutation bit flip, rate 1/n ≈1 flip per child: enough exploration without destroying a good child
Constraint handling greedy repair (drop worst efficiency, then fill) crossover and mutation regularly break capacity limits in a 5-constraint problem; repair maps them back to a nearby feasible, high-quality solution, so no evaluation is wasted on infeasible points
Replacement generational with elitism (2 best survive) best solution is never lost
Population / budget 60 individuals, 10 000 evaluations (≈166 generations) same budget for every Part 2/3 algorithm

The same GA function also implements the penalty alternative used in Part 3 (handling="penalty"), so Part 2 and Part 3 differ in exactly one component.

def tournament(pop, fit, rng, k=3):
    idx = rng.choice(len(pop), size=k, replace=False)
    return pop[idx[np.argmax(fit[idx])]]

def uniform_crossover(p1, p2, rng):
    return np.where(rng.random(len(p1)) < 0.5, p1, p2)

def bit_flip(x, rate, rng):
    y = x.copy(); y[rng.random(len(x)) < rate] ^= 1
    return y

def ga(u, d, b, handling="repair", pop_size=60, max_evals=10000, p_cross=0.9,
       mut_rate=None, k=3, n_elite=2, penalty=None, seed=0):
    # handling = "repair"  : every individual is repaired -> always feasible, fitness = utility
    # handling = "penalty" : infeasible individuals allowed, fitness = utility - penalty * violation
    # returns best FEASIBLE solution seen, its utility, per-evaluation history, evaluations, fraction of feasible evaluations
    rng = np.random.default_rng(seed)
    n = len(u)
    mut_rate = 1.0 / n if mut_rate is None else mut_rate
    eff = efficiency(u, d, b)
    lam = eff.max() if penalty is None else penalty    # lambda >= best utility per unit normalised cost
    state = dict(best_f=0.0, best=np.zeros(n, int), feasible_evals=0)

    def evaluate(x):
        v = violation(x, d, b)
        f = utility(x, u)
        if v == 0:
            state["feasible_evals"] += 1
            if f > state["best_f"]:
                state["best_f"], state["best"] = f, x.copy()
        return f - lam * v if handling == "penalty" else f

    pop = rng.integers(0, 2, (pop_size, n))
    if handling == "repair":
        pop = np.array([repair(x, u, d, b, eff) for x in pop])
    fit = np.array([evaluate(x) for x in pop]); evals = pop_size
    hist = [state["best_f"]] * pop_size                # hist[k] = best-so-far after k+1 evaluations

    while evals < max_evals:
        order = np.argsort(-fit)
        new = [pop[i].copy() for i in order[:n_elite]]
        new_fit = [fit[i] for i in order[:n_elite]]
        while len(new) < pop_size and evals < max_evals:
            a, c = tournament(pop, fit, rng, k), tournament(pop, fit, rng, k)
            child = uniform_crossover(a, c, rng) if rng.random() < p_cross else a.copy()
            child = bit_flip(child, mut_rate, rng)
            if handling == "repair":
                child = repair(child, u, d, b, eff)
            new.append(child); new_fit.append(evaluate(child)); evals += 1
            hist.append(state["best_f"])
        pop, fit = np.array(new), np.array(new_fit)
    return state["best"], state["best_f"], hist, evals, state["feasible_evals"] / evals

Part 3 — Empirical study: constraint-handling by repair vs penalty¶

Research question. In a heavily constrained problem (m=5, all models together need 1.05–3.06× the capacity) which constraint-handling mechanism uses a fixed evaluation budget better?

Variants (identical in every other respect: population 60, tournament k=3, uniform crossover p=0.9, mutation 1/n, elitism 2, same initial seeds, 10 000 fitness evaluations)

  • A – Repair: infeasible offspring are repaired (greedy drop + fill) before evaluation. All evaluated points are feasible.
  • B – Penalty: offspring are evaluated as they are, with fitness $f(\mathbf{x})-\lambda\,V(\mathbf{x})$, where $V$ is the capacity-normalised total excess and $\lambda=\max_j e_j$ (the best utility-per-normalised-cost ratio, so that exceeding a capacity never pays off at the margin). The reported solution is the best feasible point visited.

Hypothesis H1. Variant A reaches a higher final utility than B under the same budget. Reasoning: repair projects each offspring onto the feasible region using problem knowledge (efficiency), so the search effectively explores only feasible, locally-greedy-optimal solutions; the penalty GA spends part of its evaluations on infeasible points, and its best feasible solution lies near the capacity boundary where a penalised fitness gives a weak gradient.

Protocol. 30 paired runs (same seed for A and B), significance level α = 0.05, two-sided Wilcoxon signed-rank test on the paired final utilities (non-parametric: utilities are discrete and not normally distributed). H0: the paired differences are centred on zero. Effect size: median paired difference and the Vargha–Delaney $\hat A_{12}$ (probability that A beats B in a random pair; 0.5 = no effect).

Results and discussion¶

Part 1 (n=28). The steepest-ascent hill climber with restarts finished every run feasible, on average 0.28 % below the exact optimum (130 883): mean 130 523 ± 382, 8/30 runs hit the optimum, worst gap 0.76 %. The gap histogram is bimodal (≈0–0.2 % vs ≈0.65–0.75 %): runs either end in a near-optimal basin or in a distinct local optimum that a single bit flip cannot leave. The convergence curves show most progress within the first ~300 evaluations; later gains come only from restarts. This motivates a method that explores more broadly.

Part 2 (n=90). With the same 10 000-evaluation budget the GA (mean 11 189.6 ± 2.3, best 11 191) clearly beats the hill climber (10 981 ± 69, best 11 113), converges within ~1 500 evaluations and has a spread about 30× smaller. Crossover recombines good model subsets, which a one-flip neighbourhood cannot do. 11 191 was reached in several runs and also with 20 000 evaluations in preliminary tests, so it is probably (not provably) optimal; the exact value is unknown for m=5. The best solution is feasible and binds the second resource exactly (1100/1100).

Part 3 (repair vs penalty). H1 is supported. Repair gives mean 11 189.6 vs 11 155.1 for penalty; A wins 28 of 30 pairs, Wilcoxon W=3, p = 3.5e-6 (reject H0 at α=0.05), $\hat A_{12}$ = 0.95 (large). Penalty also has ~17× the standard deviation (40 vs 2.3), including one weak run (10 966), and only 56 % of its evaluations were feasible versus 100 % for repair. Trade-offs: repair costs more CPU per evaluation (≈4× here; timings are machine dependent) because of the drop and fill loops, whereas penalty is simple, needs no problem-specific heuristic, and its fitness landscape lets the search cross infeasible regions. In the equal-wall-clock check (penalty given ≈38 000 evaluations) the gap shrinks (11 176.9 ± 14.3 vs 11 189.6) but remains significant (p ≈ 2e-4; A better in 19, equal in 8, worse in 3 pairs): the advantage is not only a budget-accounting artefact.

Limitations / threats to validity.

  • Repair uses problem knowledge (efficiency ordering) that the penalty variant lacks, so the study compares mechanisms including their embedded heuristic, not penalty vs repair in isolation.
  • The penalty weight λ was set by a rule, not tuned; a tuned or adaptive penalty could narrow the gap.
  • One instance, one population size; the ceiling at 11 191 compresses the repair distribution, limiting the resolution of effect sizes.
  • Runtime figures are from one machine and vary between executions.

Reproducibility. Seeds 0–29 are fixed per run; Kernel → Restart & Run All regenerates every number except runtimes.
